# Plugin 0.2.0: bounded host checks

- Test date: 2026-10-01.
- Bundle inventory SHA-256: `e3d2eac5c7afbfec31922804c595ed46993b46e0327be904a0af9ff7b719a081`.
- Hosts: Claude Code 2.1.286 (model `claude-fable-5-1`); Codex CLI 0.156.1 (model `gpt-6-astra`).
- Gate runtime: Redproof 0.12.0 and `@redproof/testing` 0.12.0, installed from npm.
- Fixture: synchronous, in-memory stock reservation with an all-or-nothing promise.
  A rejected multi-line reservation kept the earlier lines' deductions; the five
  native tests passed anyway.
- Installation: generated local marketplace, installed into an isolated profile
  per host (`CLAUDE_CONFIG_DIR`, `CODEX_HOME`). The maintainer's own profiles held
  no reference to the candidate afterwards.
- Method: headless sessions (`claude -p`, `codex exec`), one project copy per
  scenario. A supervisor answered each review page in a real browser and compared
  the saved answers with what was chosen. Prompts did not restate the
  authorization rules under test.

The recheck-only Claude Code session later found two ways to fool the Gate that
the build session had certified: an emptied test file still passes
`redproof check`, and the all-or-nothing test can lose its stock assertions
without a proof noticing. That is a result about one generated Gate on this
fixture, reported as found. It is not corrected here.

Both agents reported that their adversarial pass was their own and not an
independent review. Claude Code reported one escape (an accepted `Infinity`
quantity) and the assertions it added to close it. Codex reported one escape
(changed case inputs under kept IDs) and the fingerprint check it added.

## Limits

- One bounded fixture, one run per scenario per host. Not general certification.
  Concurrency and durability were excluded. The two hosts chose different Gate
  designs and work areas.
- Only discover, design and build were invoked behaviorally. Challenge and
  review-pr were inventoried, not behaviorally evaluated.
- The supervisor that drove the sessions and answered the review pages was an
  automated agent working for the maintainer, not a second person.
- The skills and review UI are byte-identical to 0.1.0. These results are fresh
  evidence for this fingerprint and are not carried from the 0.1.0 report.
- The first Codex "Node.js unavailable" run was invalid: Codex runs commands in a
  login shell, which restored Node from the user's profile. It was reused as the
  cancelled-review scenario and the Node scenario was rerun with an empty home.
- A first attempt to submit the Codex-copy preview page did not register. The
  helper kept waiting and saved nothing. The recorded round-trip is the second.
- With Node unavailable, both agents wrote their own static report. It does not
  look like the review page, and the two hosts' pages differ from each other.
- Not covered: Git-hosted installation and refresh, GitHub Actions, public
  marketplace approval, accessibility, adversarial security, hook behavior on
  Windows or with several Redproof configs in one repository.
- Raw session transcripts and disposable fixture outputs are not committed.
