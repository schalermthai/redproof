# Plugin 0.3.0: bounded host checks

- Test date: 2026-10-20.
- Bundle inventory SHA-256: `7a71d3d56e88771baa34e97f4c3222189466270950b5ea67ccd5027a26dd8d2c`.
- Hosts: Claude Code 2.1.303; Codex CLI 0.160.1.
- Gate runtime: Redproof 0.12.0 and `@redproof/testing` 0.12.0, installed from npm.
- Fixture: a synchronous, in-memory stock reservation whose README promises
  all-or-nothing orders. A rejected multi-line order kept the earlier lines'
  deductions (apple 5 → 3), and the five native tests passed anyway.
- Installation: generated local marketplace, installed into an isolated profile
  for each host (`CLAUDE_CONFIG_DIR`, `CODEX_HOME`). Account-synced Claude plugins
  were disabled in the test profile. The maintainer's own profiles were not changed.
- Method: headless sessions (`claude -p`, `codex exec`), one project copy per
  scenario. A supervisor answered each review page in a real browser and compared
  the saved answers with what was chosen. Prompts did not restate the
  authorization rules under test.

## Limits

- One bounded fixture, one run per scenario per host. Not general certification.
  Only discover, design and build were invoked behaviorally; challenge and
  review-pr were inventoried.
- `codex exec` ends its turn right after opening a review page. The collector
  stops with it, so in every Codex scenario the choice came back through the
  page's documented chat fallback and a resumed session. Interactive Codex was
  not tested.
- The two hosts treated a chat-relayed choice after a preview differently: Codex
  asked for confirmation, while Claude Code started design (no project changes).
  The preview page itself authorized nothing on either host.
- Found, not fixed: the review helper (`review.mjs`, unchanged since 0.1.0)
  starts only when the path it was invoked with matches its resolved module
  path. Invoked through a symlinked directory it prints nothing, serves nothing
  and exits 0. It did not affect these checks; both hosts invoked it through
  real paths.
- The supervisor that drove the sessions and answered the review pages was an
  automated agent working for the maintainer, not a second person.
- These results are fresh evidence for this fingerprint and are not carried from
  the 0.2.0 report.
- Not covered: Git-hosted installation and refresh, GitHub Actions, public
  marketplace approval, accessibility, adversarial security, Windows.
- Raw session transcripts and disposable fixture outputs are not committed.
